RepLab Rust API

Native server, PostgreSQL, API version /api/v1. This is a static reference, not Swagger.

All API routes except login require Authorization: Bearer <access_token>.

MethodPathPurpose
GET/health/live, /health/readyProcess/database health
POST/api/v1/auth/loginServer password only
GET/api/v1/auth/meCurrent administrator
POST/api/v1/auth/resumeVerify remembered key; renew 90-day idle lifetime
POST/api/v1/auth/logoutRevoke current session
POST/api/v1/auth/change-passwordVerify current password; revoke all own sessions
GET, POST/api/v1/adminsLegacy account API; second-admin creation refused
GET, PUT/api/v1/settingsRead/replace gym settings
GET, POST/api/v1/membersDirectory/registration
GET/api/v1/members/{uuid}Basic profile
GET/api/v1/dashboard/summaryReal registered-member counts

Request bodies

Login: {"password":"your password"}
Password change: {"current_password":"...","new_password":"15+ characters"}
Settings: {"gym_name":"Gym Name","phone":"","address":""}
Member: {"name":"Member Name","phone":"+91 9876543210"}

Optional member fields: email, address, emergency_phone, notes, joined, is_active. Joining date defaults to today's IST date and cannot be in the future.

Directory query parameters: q (name/phone/exact member number), active (record status), limit (1–100, default 50), offset (nonnegative). Responses include items, total, limit, offset.

Login returns access_token, token_type, expires_at, admin. Sessions have a 90-day idle lifetime. Resume has no body and returns expires_at, admin after verifying the saved bearer key. Only key hashes are stored on the server. Sign-out revokes the current key; password changes revoke all keys.

There is one administrator, no default password, and no username/email requirement. The executable's create-admin command prompts for password and confirmation only. HTTPS port 8443 is fixed in the app and server. Readiness requires schema 2.

Error format: {"error":{"code":"...","message":"..."}}. Request IDs are in X-Request-ID. Login rate-limit responses include Retry-After.

Attendance, subscriptions, billing and terminal integration are not available yet. Unavailable dashboard totals are null, not invented zeros. An active member record does not establish entry rights.
