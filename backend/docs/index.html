RepLab Rust API

Native server, PostgreSQL, API version /api/v1. This is a static reference, not Swagger.

All API routes except login require Authorization: Bearer <access_token>.

MethodPathPurpose
GET/health/live, /health/readyProcess/database health
POST/api/v1/auth/loginServer password only
GET/api/v1/auth/meCurrent administrator
POST/api/v1/auth/resumeVerify remembered key; renew 90-day idle lifetime

GET, POST/api/v1/membersDirectory/legacy basic registration

Request bodies

Login: {"password":"your password"}
Password change: {"current_password":"...","new_password":"15+ characters"}
Settings: {"gym_name":"Gym Name","phone":"","address":""}
Member: {"name":"Member Name","phone":"+91 9876543210"}

Optional member fields: email, address, emergency_phone, notes, joined, is_active. Joining date defaults to today's IST date and cannot be in the future.

Directory query parameters: q (name/phone/exact member number), active (record status), limit (1–100, default 50), offset (nonnegative). Responses include items, total, limit, offset.

Login returns access_token, token_type, expires_at, admin. Sessions have a 90-day idle lifetime. Resume has no body and returns expires_at, admin after verifying the saved bearer key. Only key hashes are stored on the server. Sign-out revokes the current key; password changes revoke all keys.

There is one administrator, no default password, and no username/email requirement. The executable's create-admin command prompts for password and confirmation only. HTTPS port 8443 is fixed in the app and server. Server 0.4 requires schema 3.

Complete member enrollment

Fetch /api/v1/enrollment-options before collecting payment. Silver costs ₹1,200/₹3,200/₹6,000/₹12,000 and Gold ₹1,700/₹4,700/₹9,000/₹18,000 for 1/3/6/12 calendar months. Personal training is ₹5,000/month; insurance ₹200/month. UPI payee: 8943521009@yescred, RepLab Fitness.

{
  "request_id": "00000000-0000-4000-8000-000000000001",
  "member": {"name":"Test Member","phone":"+91 9876543210",
             "address":"Synthetic address","emergency_phone":"+91 9876543211"},
  "photo_base64": "<base64 JPEG/PNG profile photo>",
  "plan_code": "gold", "months": 3, "starts_on": "<today's IST YYYY-MM-DD>",
  "training_months": 1, "insurance_months": 2,
  "payment_method": "upi", "payment_reference": "optional reference",
  "payment_confirmed": true
}

POST this to /api/v1/members/enroll only after staff verifies the full amount received. This example totals ₹10,100 (1,010,000 integer paise). Client totals are rejected. Required: address/emergency phone, photo, plan and explicit full-payment confirmation. Cash/UPI only; QR scanning is not bank verification. Add-ons have independent durations 0 through the plan duration and start with the plan. Start date is today through 366 days ahead. End dates are inclusive, clamped monthly anniversary minus one day.

Photos are JPEG/PNG, at most 2 MiB decoded and 1024×1024 pixels. The server strips metadata and stores a 512×512-or-smaller JPEG in PostgreSQL. The enrollment JSON limit is 3 MiB; other routes remain limited to 16 KiB. This is a profile photo, not a biometric template or terminal enrollment. Insurance selection does not issue an insurance policy.

Member, photo/subscription, numbered append-only receipt and audit commit together. Generate a new UUID for each registration. Retry the exact same payload/ID after a timeout to get the same member/receipt, or GET /api/v1/enrollments/{request_id} to check the result. Do not collect payment again. Changed reuse of an ID gives 409 enrollment_conflict; missing lookup gives 404 enrollment_not_found. Full profiles contain enrollment and JPEG photo_base64 when registered; old member records do not invent plans/payments.

Error format: {"error":{"code":"...","message":"..."}}. Request IDs are in X-Request-ID. Login rate-limit responses include Retry-After.

Attendance, renewals/refunds, billing reports and terminal integration are not available yet. Unavailable dashboard totals are null, not invented zeros. An active member record does not establish entry rights.
